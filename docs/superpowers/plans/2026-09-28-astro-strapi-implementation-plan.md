# 众祺体育：Astro + Strapi 实施计划

## 已确认目标

- 面向中国大陆访客和运营团队。
- 前台采用 Astro 静态生成；正式生产部署预留腾讯云 COS + EdgeOne/CDN。
- 后台采用 Strapi，运营人员可维护文章、术语、赛事、球拍、人民币价格、站内购买入口与 Club Edits。
- 保留现有网站的暖白、近黑与运动绿视觉语言，以及赛事、知识、装备和 Club Edits 的内容框架。
- 选拍攻略为 4 题、3 支建议、“再调一点”标签；雷达图只展示结果。
- 技术文章页可直接展示 2–3 支关联球拍，不把用户强制跳到商城筛选页。

## 分期实施

### 第一阶段：本地可运行的内容站

1. 建立 Astro 项目与原始静态站隔离的迁移目录。
2. 抽取全站布局、导航、页脚、赛事、知识、球拍网格与 Club Edits 组件。
3. 将现有 17 款球拍、知识文章和页面文案迁入本地内容文件，保持现有 URL 的重定向策略。
4. 实现中文响应式前台和站内商品详情页。

### 第二阶段：可编辑后台

1. 建立 Strapi 项目和内容类型：网站设置、赛事、文章、术语、球拍、Club Edits。
2. 添加球拍性能字段、文章训练能力与球拍推荐覆盖字段。
3. 设置管理员、内容编辑、商品运营三类权限。
4. 用现有静态内容作为初始导入数据。

### 第三阶段：选拍与内容转化

1. 在商城页添加 4 题选拍攻略。
2. 按后台球拍标签与性能评分给出三支建议与理由。
3. 加入“再调一点”标签与雷达图展示。
4. 在技术文章底部生成可被编辑覆盖的球拍推荐模块。

### 第四阶段：发布、性能与大陆部署

1. Strapi 发布事件触发 Astro 静态构建。
2. 将构建产物上传腾讯云 COS，并由 EdgeOne/CDN 分发。
3. 配置正式域名、ICP 备案后的 HTTPS、缓存刷新与回滚策略。
4. 完成移动端、无障碍、减少动态效果与发布失败回退验证。

## 当前实现边界

- 本轮先实施第一阶段，并同时建立可供第二阶段接入的内容接口边界。
- “网站内购买”的订单、支付、库存与支付服务商尚未确定；本地前台先提供商品详情与购买流程接口位，不假设或接入具体支付平台。
- 腾讯云账号、域名、ICP 备案和正式支付服务商账号由用户方后续提供后再进入部署与真实交易联调。

## 验收点

- `npm run dev` 可本地启动 Astro 前台。
- 首页、商城、商品详情和文章页通过统一布局运行。
- 现有视觉语言、移动端导航与球拍信息不丢失。
- 内容来源通过一层数据接口读取，后续可从本地内容替换为 Strapi API，不需要重写页面组件。
