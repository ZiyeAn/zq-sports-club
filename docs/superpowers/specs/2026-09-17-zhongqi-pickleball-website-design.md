# 众祺匹克球俱乐部网站 · 设计规格

日期：2026-09-17  
状态：待用户审阅  
范围：第一版展示型官网

## 1. 目标与受众

网站服务于成人业余运动爱好者与高端会员。它应让初次来访者感到众祺既理解匹克球，也具备成熟、值得加入的俱乐部气质。

第一版的优先级为：

1. 用匹克球基础知识、技巧与全球重点赛事建立内容权威。
2. 塑造众祺匹克球俱乐部的社群与生活方式定位。
3. 展示 Warping Point Pickleball Paddle 的代理装备与选择建议。
4. 为未来的匹克球周边销售保留 Club Edits 入口。

面向用户的主要语言为中文；国际赛事保留官方英文名称，球拍及配件保留英文品牌与型号。

## 2. 品牌与视觉方向

对外名称使用“众祺匹克球俱乐部”，英文辅助名称为 `ZHONGQI PICKLEBALL CLUB`。定位语言：训练、赛事、装备与同频伙伴，在这里持续上场。

视觉采用“编辑感 × 高端运动俱乐部 × 潮流社群”。参考图只提取其设计 DNA，不进行像素级复刻：

- 暖白纸张感底色、近黑文字与细网格。
- 荧光运动绿作为单一高亮，用于赛事状态、互动、关键行动与运动符号。
- 大比例中文标题、强烈字号反差、不对称留白与杂志化编排。
- 真实比赛、球员与球拍图片优先采用黑白或低饱和处理；没有真实素材的位置使用明确的可替换编辑占位。
- 采用 Logo v2。

动效采用“克制运动感”：首屏元素短促错落淡入；滚动内容轻微显现；卡片悬停时边框或绿色标记反馈、图片极轻微放大；允许一个绿色球沿网格移动的浏览提示。所有动效均提供减少动态效果降级，且不影响阅读与赛事扫描。

## 3. 信息架构与首页内容顺序

首页遵循“装备社群”的叙事外壳，但知识和赛事比装备优先：

1. **首屏 / 俱乐部身份**：众祺匹克球俱乐部的主张、运动氛围与“即将开放”行动入口。
2. **全球赛事**：重点巡回赛、公开赛与职业赛事的精选赛事卡；展示赛事名称、地区、日期、来源和“为什么值得看”。
3. **匹克球知识与技巧**：基础规则、打法、技巧与入门内容，作为持续回访的主内容层。
4. **Warping Point 装备**：球拍品牌介绍、型号与面向不同打法的选择建议，不虚构价格、库存或代理关系之外的商品信息。
5. **Club Edits**：匹克球周边预告，明确标记为“即将开放”。
6. **关于众祺 / 页脚**：简短品牌定位与未来加入、报名、购买、合作入口。

顶级导航为：首页、赛事、知识、装备、Club Edits。第一版所有加入、报名、购买与合作入口统一写作“即将开放”；不得提交空表单或暗示已开放的服务。

## 4. 第一版实现边界

第一版是响应式展示型官网，不包含账户体系、后台、自动抓取、自动刷新赛事、报名、下单、支付或库存管理。

赛事与资讯卡以可替换的编辑结构呈现。可以引用已核实的公开资料链接，并显示来源与更新时间；在没有后端或明确授权数据源时，不宣称“实时更新”。将来可将内容数组替换为数据接口，逐步扩展为内容型网站或可运营平台。

预计建立的前端工件如下（实施计划阶段可依据实际项目结构微调）：

- `index.html`：单页语义化结构与内容区域。
- `tokens.css`：品牌色、字体、间距、字号、圆角、动效等设计令牌。
- `styles.css`：网格、响应式布局、交互状态与无障碍样式。
- `script.js`：轻量的导航、渐进显现、可访问的交互与减少动态效果处理。
- `.hallmark/log.json`：本次视觉结构的设计记忆。

不会删除现有品牌素材、Logo 或视觉参考文件。既有 `Logo v2` 文件仅作为读取和引用对象。

## 5. 组件、数据与故障处理

组件以可独立替换的内容模块组织：导航、首屏、赛事卡、知识卡、装备卡、周边预告、页脚。所有链接、按钮和导航均具备默认、悬停、焦点、按下、禁用或“即将开放”语义状态。

内容数据模型至少包含标题、类别、摘要、时间、来源、图片状态与目标链接。图片缺失时显示统一占位；缺少赛事日期、来源或具体型号时显示“信息待确认”，不得补造数据。外部链接不可用时，页面保持可阅读并不显示虚假的成功状态。

## 6. 可用性与验收

- 在 320、375、414、768 像素宽度与桌面宽度检查，无横向滚动。
- 触控目标、导航、文字链接与“即将开放”入口在移动端保持单行、易点按。
- 标题可断行但不溢出；图片网格使用可收缩的列定义。
- 键盘焦点清晰可见，动画遵从 `prefers-reduced-motion`。
- 不使用虚构统计、客户评价、库存、售价、赛事成绩或代理声明。
- 使用真实素材前确认使用权；参考图只作为风格参考，不作为站点成品素材。

## 7. 后续演进

第二阶段可选接入经过许可的赛事数据源或人工编辑后台；第三阶段可增加社群申请、预约、商品库存、购物车与支付。每个阶段均应单独确认数据来源、运营责任、隐私与交易要求。
